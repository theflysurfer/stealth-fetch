## Décisions

1. **`--no-sandbox` + `--disable-dev-shm-usage` par défaut**
   - **Choix** : toujours passer ces flags à `nodriver.start()`
   - **Rationale** : Chrome refuse de démarrer en user non-root sans `--no-sandbox`. `/dev/shm`
     peut être trop petit dans certains contextes serveur → `--disable-dev-shm-usage` en prévention.
   - **Alternative rejetée** : conditionner au runtime (détection root) — complexité inutile, ces
     flags sont sans danger en headless sur un service interne.

## Problèmes

1. **nodriver hang sans `--no-sandbox`**
   - **Symptôme** : `nodriver.start(headless=True)` bloque indéfiniment (timeout 30s), aucune erreur.
   - **Cause** : Chrome exige `--no-sandbox` pour les utilisateurs non-root. Sans, le processus
     Chrome ne démarre jamais et nodriver attend indéfiniment la connexion CDP.
   - **Solution** : ajout de `browser_args=["--no-sandbox", "--disable-dev-shm-usage"]` dans
     `engines/stealth.py`.
   - **Prévention** : documenté dans CLAUDE.md (Gotchas).

2. **Patch direct VPS bloquant le git pull**
   - **Symptôme** : `git pull` échoue avec `error: Your local changes would be overwritten`.
   - **Cause** : patch appliqué directement sur le VPS avant le commit/push GitHub.
   - **Solution** : `git checkout -- stealth_fetch/engines/stealth.py` puis `git pull`.
   - **Prévention** : toujours committer et pousser avant de déployer sur le VPS (miroir git).
