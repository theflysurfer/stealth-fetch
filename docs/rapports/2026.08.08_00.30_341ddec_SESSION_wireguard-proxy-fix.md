## Objectif

Diagnostiquer et corriger les 28 domaines CONN_FAIL du benchmark proxy résidentiel (tunnel WireGuard Freebox).

## Réalisations

### Diagnostic du tunnel WireGuard

Le tunnel `freebox-yt` utilise `Table = 42` avec `fwmark 42` comme unique chemin de routage. microsocks (SOCKS5 proxy) bind ses paquets sortants à `192.168.27.65` (IP WG) mais ne pose **aucun fwmark** → les paquets tombent dans la table main → source IP privée non routable → connexion morte.

### Fix : source-based routing rule

```bash
ip rule add from 192.168.27.65 table 42 priority 32764
```

Ajouté au `PostUp`/`PostDown` de `/etc/wireguard/freebox-yt.conf` pour persistance.

## Décisions

- **Source-based routing plutôt que fwmark iptables** : plus simple, pas besoin de mangle table.
  Le fwmark reste pour les clients qui le posent explicitement (youtube-manager).
- **NXDOMAIN = problème de données**, pas d'infra. Les noms de domaines viennent de la liste
  Allocine/benchmark, certains sont juste faux. À corriger dans les consommateurs.

## Problèmes

- SSH VPS intermittent (15s timeout fréquents, plafond de sous-processus Git Bash).
  Contourné avec `timeout` et commandes combinées.
- Deux `sed` ont appliqué → PostUp dupliqué, corrigé via `python3 -c`.
