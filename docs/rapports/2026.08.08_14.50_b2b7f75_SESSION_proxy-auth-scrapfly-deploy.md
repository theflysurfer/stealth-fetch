## Objective

Intégrer le proxy résidentiel Webshare (HTTP rotatif) dans la cascade, corriger les faux positifs
de détection DataDome/Akamai, améliorer Camoufox avec humanize+geoip, et configurer Scrapfly comme
niveau 5 SaaS de secours. Déployer les secrets proxy et API key sur le VPS via credstore systemd.

## Achievements

- **Nodriver : rejet proxy authentifié** : Chrome `--proxy-server` ne supporte pas `user:pass@host:port`.
  Ajout de `_strip_proxy_auth()` qui lève RuntimeError → la cascade tombe directement sur Camoufox
  (qui gère l'auth proxy via Playwright).
- **Faux positifs DataDome/Akamai corrigés** : `is_blocked()` ne signale plus un status 200 avec
  >5 Ko de HTML comme bloqué pour DataDome/Akamai — le SDK JS de ces protections est présent sur
  toutes les pages, y compris les pages qui se sont chargées correctement.
- **Camoufox amélioré** : ajout de `humanize=True` (simulation de comportement humain) et
  `geoip=True` (cohérence géographique du fingerprint avec l'IP de sortie proxy).
- **Cascade log visibility** : les messages « blocked » passés de `log.info` à `log.warning` —
  visibles dans journalctl malgré le niveau WARNING par défaut d'uvicorn.
- **last_error fidèle** : mis à jour aussi sur les résultats bloqués (pas seulement sur les
  exceptions) — le message d'erreur final reflète le vrai dernier échec.
- **Scrapfly configuré** : clé API stockée en credstore (`stealth-fetch-scrapfly-key`), level 5
  actif dans le health check. Docstring corrigée (level 5, pas 4).
- **Proxy Webshare en credstore** : URL complète du proxy rotatif résidentiel stockée dans
  `stealth-fetch-proxy`, chargée au démarrage via `STEALTH_FETCH_PROXY`.
- **Cookie dict Camoufox** : retiré le champ `url` du dict cookies — Playwright veut `domain` OU
  `url`, pas les deux.
- **Résultat des irréductibles** : viator.com et tripadvisor.fr passent maintenant (c'étaient des
  faux positifs DataDome). 3 restent bloqués : britishmuseum.org, terra-botanica.com, museodelprado.es.

## Decisions

1. **Rejet proxy auth dans nodriver plutôt que tentative de CDP auth**
   - **Choix** : RuntimeError dans `_strip_proxy_auth()` → cascade vers Camoufox
   - **Rationale** : Chrome CDP ne supporte pas l'auth proxy HTTP de manière fiable ; Playwright/Camoufox
     le fait nativement via le dict `{server, username, password}`. Laisser la cascade faire son travail.
   - **Alternative rejetée** : CDP `Fetch.requestPaused` avec header `Proxy-Authorization` — fragile,
     non maintenu, casse sur les WebSocket.

2. **Seuil >5 Ko pour DataDome/Akamai au lieu d'ignorer la détection**
   - **Choix** : `status == 200 and len(html) > 5000` → pas bloqué pour ces deux protections
   - **Rationale** : une page de challenge DataDome/Akamai fait ~2-3 Ko ; une page réelle en fait 50+.
     Le seuil discrimine fiablement entre challenge et page avec SDK de protection embarqué.

3. **Scrapfly en level 5 de secours (pas de bascule automatique)**
   - **Choix** : `max_level=3` par défaut dans `FetchRequest`, Scrapfly accessible seulement en
     demandant explicitement `max_level=5`
   - **Rationale** : plan gratuit limité (1000 crédits) — réservé aux cas où les 4 moteurs locaux
     échouent, pas en usage courant.

## Problems

1. **Nodriver échoue silencieusement avec proxy authentifié**
   - **Symptôme** : Chrome se lance, charge une page blanche, timeout
   - **Cause** : `--proxy-server=http://user:pass@host:port` → Chrome ignore les credentials, se
     connecte au proxy sans auth, le proxy refuse
   - **Solution** : `_strip_proxy_auth()` détecte les credentials et lève RuntimeError
   - **Prévention** : commentaire dans le code + gotcha CLAUDE.md

2. **viator.com et tripadvisor.fr marqués comme bloqués malgré succès**
   - **Symptôme** : via le service HTTP, la cascade escalade alors que le CLI Python fonctionne
   - **Cause** : `is_blocked()` détectait "datadome" dans le HTML (SDK JS DataDome présent sur
     toutes les pages, même les pages bien chargées)
   - **Solution** : ne pas flagger status 200 + >5 Ko pour DataDome/Akamai
   - **Prévention** : règle dans CLAUDE.md

3. **Logs `stealth_fetch` invisibles dans journalctl**
   - **Symptôme** : `log.info("engine=... blocked=...")` n'apparaît pas
   - **Cause** : le root logger d'uvicorn est à WARNING ; le logger `stealth_fetch` propage au root
   - **Solution** : messages de blocage passés à `log.warning()`
   - **Prévention** : gotcha dans CLAUDE.md

4. **Premier appel Camoufox+geoip timeout**
   - **Symptôme** : timeout sur la première requête après `pip install camoufox[geoip]`
   - **Cause** : téléchargement GeoLite2 (~45 Mo) à la première utilisation de `geoip=True`
   - **Solution** : la base est mise en cache après le premier appel, les suivants sont rapides
   - **Prévention** : gotcha documenté

5. **last_error trompeur après un blocage Camoufox**
   - **Symptôme** : `last_error` montrait l'erreur proxy de stealth (level 3) alors que c'est
     Camoufox (level 4) qui était bloqué
   - **Cause** : `last_error` n'était mis à jour que sur exception, pas sur détection de blocage
   - **Solution** : `last_error` mis à jour dans la branche `is_blocked()` aussi

### Gotchas

- **Chrome `--proxy-server` n'accepte pas `user:pass@host:port`** : pas de contournement fiable
  via CDP. Laisser la cascade tomber sur Camoufox qui gère l'auth proxy nativement.
- **DataDome/Akamai SDK = faux positifs** : la string "datadome" / "akamai" dans le HTML d'une
  page 200 ne signifie PAS un blocage — c'est le SDK de monitoring, présent sur toutes les pages.
- **Camoufox GeoIP premier lancement** : ~45 Mo de téléchargement GeoLite2, prévoir un timeout
  plus long ou pré-télécharger.
- **uvicorn loglevel** : le root logger est à WARNING — utiliser `log.warning()` pour les messages
  opérationnels importants (blocage, erreur), pas `log.info()`.
