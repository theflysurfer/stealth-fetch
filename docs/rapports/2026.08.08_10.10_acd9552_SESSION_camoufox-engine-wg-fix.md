# Session : Camoufox engine + fix routage WireGuard

## Metadata
- **Date** : 2026-08-08 10:10
- **Duration** : ~2 heures
- **Commit(s)** : acd9552
- **Project** : 2026.08 Stealth Fetch
- **Branch** : main

## Objective

Ajouter un moteur anti-détection Firefox (Camoufox) comme niveau 4 de la cascade, améliorer le
challenge handling de nodriver, et corriger le routage WireGuard qui empêchait 28 domaines de se
connecter via le tunnel résidentiel.

## Achievements

- **Moteur Camoufox** (level 4) : Firefox anti-détection via Playwright, fingerprint différent
  de Chrome, uBlock Origin intégré. Débloque 4 des 9 domaines CF_BLOCK (musee-orsay.fr, kew.org,
  si.edu, amnh.org).
- **Nodriver amélioré** : détection du challenge Cloudflare ("Just a moment...", `challenge-running`,
  `__cf_chl`) + attente jusqu'à 12s pour auto-résolution + tentative de clic Turnstile. N'a pas
  suffi seul pour les 9 CF_BLOCK, mais robustifie le level 3 pour les futurs sites.
- **Fix routage WireGuard** : ajout de `ip rule add from 192.168.27.65 table 42 priority 32764`
  dans PostUp/PostDown — les paquets de microsocks (SOCKS5 proxy résidentiel) n'avaient pas le
  fwmark 42, tombaient dans la table main et mouraient. Fix persisté dans
  `/etc/wireguard/freebox-yt.conf`.
- **Diagnostic NXDOMAIN** : 9 des 28 domaines CONN_FAIL étaient des noms de domaines invalides
  (palais-tokyo.com → palaisdetokyo.com, etc.), pas un problème d'infra.
- **Cascade réordonnée** : 1=direct, 2=curlffi, 3=nodriver, 4=camoufox, 5=saas (Scrapfly repoussé
  à level 5, non utilisé).

## Decisions

1. **Camoufox plutôt que Scrapfly**
   - **Choix** : moteur open-source (Firefox anti-détection) au lieu de SaaS payant
   - **Rationale** : pas de coût, pas de clé API, fingerprint Firefox fondamentalement différent de
     Chrome — adresse la cause du blocage (détection de fingerprint), pas seulement l'IP
   - **Alternative rejetée** : Scrapfly (payant, dépendance externe, aucun contrôle)

2. **Source-based routing plutôt que iptables fwmark**
   - **Choix** : `ip rule add from 192.168.27.65 table 42`
   - **Rationale** : plus simple et direct — pas besoin de mangle table ni de connaître le PID de
     microsocks. Le fwmark reste pour youtube-manager qui le pose explicitement.

## Problems

1. **Routage WireGuard ne routait pas microsocks**
   - **Symptôme** : 28/39 domaines en CONN_FAIL (http=000, 15ms) via le proxy SOCKS5
   - **Cause** : seul le fwmark 42 routait vers la table 42 ; microsocks ne pose pas de fwmark
   - **Solution** : source-based routing rule dans le PostUp WG
   - **Prévention** : documenté dans le diary + commentaire dans la config WG

2. **9 domaines NXDOMAIN**
   - **Symptôme** : `dig palais-tokyo.com @8.8.8.8` → NXDOMAIN
   - **Cause** : noms incorrects dans la liste benchmark d'Allocine
   - **Solution** : à corriger dans la source de la liste benchmark

### Gotchas

- **VPS pip** : utiliser `.venv/bin/pip`, pas `pip` système (PEP 668 bloque)
- **Camoufox fetch** : après `pip install camoufox`, lancer `.venv/bin/python -m camoufox fetch`
  pour télécharger le binaire Firefox (~660 Mo)
- **WG source routing** : la règle `from 192.168.27.65 table 42 priority 32764` est dans le
  PostUp, elle survivra à un restart du tunnel. Vérifier avec `ip rule list`
- **Camoufox sans proxy** : fonctionne pour si.edu et amnh.org (fingerprint seul suffit).
  musee-orsay.fr et kew.org ont besoin du proxy résidentiel EN PLUS de Camoufox
