## Objective

Exécuter le handoff de la session précédente : corriger les domaines NXDOMAIN du benchmark,

## Achievements

- **Correction de 18 domaines NXDOMAIN** : tous les noms invalides du benchmark (34% de la liste)
  ont été corrigés via recherche web + vérification DNS. Lot posté sur issue #2.
- **terra-botanica.com résolu** : domaine parqué sur Sedo (en vente), pas un site protégé. Remplacé
  par `terrabotanica.fr` (le vrai site du parc).
- **Benchmark v5 avec proxy** : 30/47 OK (63%), contre 19/50 (38%) sans proxy. Le proxy résidentiel
  Webshare débloque les sites protégés par Cloudflare qui bloquent l'IP datacenter.
- **Bug proxy-SSL découvert et corrigé** (`cascade.py`) : le proxy HTTP Webshare (port 80) interfère
  avec le handshake SSL de certains sites → erreurs WRONG_VERSION_NUMBER, PROXY_BAD_GATEWAY, etc.
  Le fix retry le même moteur sans proxy quand une erreur SSL caractéristique du proxy est détectée.
  Même logique pour les `generic-block` avec proxy sur camoufox/stealth.
- **Benchmark v5b avec proxy-retry** : 29/47 (61%). Le fix est techniquement correct mais n'améliore
  pas le score VPS car les sites qui échouent via proxy bloquent aussi l'IP datacenter nue.
- **tripadvisor.fr débloqué** : passe désormais en camoufox avec proxy (14497 ms, 405 Ko).
- **Résultats v5 et v5b postés sur issue #2** (3 commentaires au total).

## Decisions

1. **Conserver le fix proxy-retry malgré un score v5b légèrement inférieur**
   - **Choix** : commit du fix tel quel
   - **Rationale** : le fix est correct pour le cas d'usage réel (consommateur avec proxy résidentiel
     où l'IP directe passe mais le proxy cause des erreurs SSL). Le benchmark VPS ne le montre pas
     car les sites échouent des deux côtés (proxy et datacenter IP). grotte-cerdon.com est intermittent.
   - **Alternative rejetée** : retirer le fix — perdrait la robustesse pour les cas proxy-SSL réels.

## Problems

1. **Proxy Webshare cause des erreurs SSL sur certains sites**
   - **Symptome** : WRONG_VERSION_NUMBER, PROXY_BAD_GATEWAY, SEC_ERROR_UNKNOWN_ISSUER sur ~10 domaines
   - **Cause** : le proxy HTTP (port 80) interfère avec le tunnel CONNECT SSL pour certains sites
   - **Solution** : détection des marqueurs SSL proxy-induits (`_PROXY_SSL_MARKERS`) et retry sans proxy
   - **Prevention** : liste de marqueurs extensible, couvre les erreurs vues sur httpx/curl_cffi/nodriver/camoufox

2. **Pyright "kwargs is possibly unbound"**
   - **Symptome** : erreur pyright sur la construction de `kwargs_no_proxy` dans le handler d'exception
   - **Cause** : `kwargs` défini dans le bloc `try`, potentiellement non lié dans `except`
   - **Solution** : construire `kwargs_no_proxy` depuis les paramètres de la fonction (`timeout`, `headers`,
     `cookies`) au lieu de filtrer `kwargs`
   - **Prevention** : ne jamais référencer une variable du `try` dans le `except` sans vérifier qu'elle
     est liée

3. **SSH timeouts récurrents pendant le benchmark**
   - **Symptome** : commandes SSH coupées, pas de sortie
   - **Cause** : VPS sous charge (benchmark lance des navigateurs headless)
   - **Solution** : téléchargement des logs via SCP, commandes PowerShell pour contourner
