## Decisions

1. **Benchmark sans proxy (résultat partiel)**
   - **Choix** : le benchmark a tourné sans proxy (env var `STEALTH_FETCH_PROXY` non disponible en SSH)
   - **Rationale** : le credstore systemd ne set l'env var que pour le processus du service, pas pour
     les sessions SSH interactives. Un re-run avec proxy explicite est nécessaire.
   - **Impact** : les résultats sous-estiment la cascade — certains domaines Cloudflare-blocked passeraient
     avec l'IP résidentielle.

## Problems

1. **Env var credstore non disponible en SSH**
   - **Symptôme** : `Proxy: none` dans la sortie du benchmark
   - **Cause** : `STEALTH_FETCH_PROXY` est chargé via `LoadCredentialEncrypted` dans l'unit systemd,
     pas dans l'environnement utilisateur SSH
   - **Solution** : pour le prochain benchmark, lire le proxy depuis le PID du service
     (`cat /proc/$(systemctl show stealth-fetch -p MainPID --value)/environ | tr '\0' '\n' | grep STEALTH_FETCH_PROXY`)
     ou passer le proxy en argument CLI
   - **Prévention** : documenter dans gotchas

2. **Liste benchmark contient ~34% de NXDOMAIN**
   - **Symptôme** : 17+ domaines en `NS_ERROR_UNKNOWN_HOST`
   - **Cause** : les noms de domaines proviennent d'activity-scraper/Waaker, non vérifiés à la source
   - **Solution** : corriger les noms un par un (recherche web du vrai nom officiel de chaque site)

### Gotchas

- **Credstore env vars invisibles en SSH** : les variables chargées via `LoadCredentialEncrypted` ne
  sont disponibles que dans le processus du service systemd. Pour les lire en SSH : inspecter
  `/proc/<PID>/environ` du service (nécessite sudo).
- **~34% de la liste benchmark est NXDOMAIN** : problème de qualité de données en amont
  (activity-scraper/Waaker), pas de stealth-fetch.
- **puy-du-fou.com** : erreur SSL (`TLSV1_UNRECOGNIZED_NAME`) — le certificat ne couvre pas ce nom
  de domaine. Probablement une redirection vers `www.puydufou.com`.
